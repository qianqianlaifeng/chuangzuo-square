# 创作广场 · 视频

网页版复刻豆包手机 App 的「**视频创作广场**」—— 两列瀑布流，每条都能看**生成效果 + 完整提示词**。

打开网址即看，**手机浏览器直接可用**，不用装 App、不用分享。

---

## 它是怎么工作的

```
访客（手机/电脑，无需登录）
      │  打开网址
      ▼
┌─────────────────────────────┐
│  server.py（Python 单文件）   │
│  · 同域代理，绕开 CORS        │
│  · 视频/封面代理，绕开防盗链   │
│  · 实时调用豆包接口           │
└─────────────────────────────┘
      │  用站主的豆包登录态
      ▼
   豆包创作广场 feed
```

未开通实时广场时，自动降级为「公开作品墙」—— 页面照常能用，只是内容少。

---

## 两种用法

### A. 实时广场（推荐，内容自动更新）

需要**站主**配置一次，配置对**所有访客生效**：

1. 站主在**电脑**浏览器打开 [doubao.com](https://www.doubao.com/) 并登录（豆包 App 的账号也行）
2. 按 **F12** 打开控制台，粘贴执行：
   ```
   copy(document.cookie)
   ```
3. 打开本站 → 点右上角 **⚙️** → 粘贴 Cookie → 点「保存并开启实时广场」

之后**任何人打开网址都是满屏实时内容**，本人无需登录。

### B. 公开作品墙（免配置）

不配置也能看：点右上角 **＋** 粘贴豆包 App 里的分享链接（分享 → 复制链接），作品实时上墙，视频和提示词都是当场从豆包拉取的。

## 为什么是「站主配置一次」，不是「每人登录各的」

这一条实测过，不是偷懒：

| 尝试 | 结果 |
|---|---|
| 服务端调 `/passport/web/login/sms/`（手机验证码） | `error_code:16 请使用应用权限` |
| 服务端调 `/passport/web/login/qrcode/`（扫码） | 同样 `error_code:16` |
| 游客会话打 `/api/`（首页 cookie + webid） | 依然 `401` |
| 访问者自己在手机上登录 | ❌ 手机没有 F12，取不到自己的 Cookie |

豆包的登录接口是 **App 专属风控**，服务端模拟不了；手机也导不出 Cookie。所以「每个访问者登录自己的账号」在技术上不成立。

站主共享是唯一能落地的形态。好在广场内容本来就是公开的，访客看到的是**同一份实时广场**，不影响使用。

完整实测记录见 `_old/接口实测结论-最终版.md`。

## 部署（免费，手机可开）

项目是纯标准库 Python，零第三方依赖。

**Render**（一键）

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/qianqianlaifeng/chuangzuo-square)

**HuggingFace Spaces**（Docker 模式）

 Spaces 里 New → Docker → 指向本仓库即可。

> ⚠️ 不要用 GitHub Pages：纯静态托管跑不了代理，视频会被防盗链拦掉。

部署完拿到网址（形如 `https://xxx.onrender.com`），手机浏览器直接打开就行。
**Cookie 只存在服务器内存里**，不落盘、不外传；服务重启或过期后站主重新贴一次。

## 接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 实时广场是否已开通 |
| GET | `/api/feed?cursor=&count=` | 实时广场信息流（下游翻页） |
| POST | `/api/owner/login` | 站主贴 Cookie，全站生效 |
| POST | `/api/owner/logout` | 关闭实时广场 |
| GET | `/api/works` | 公开作品列表 |
| POST | `/api/works` | 添加公开作品链接 |
| GET | `/api/resolve?share_id=&vid=` | 实时调用豆包，返回视频/作者/提示词 |
| GET | `/api/stream?url=` | 视频/封面代理（支持 Range） |

---

## 技术要点

- **同域代理是必须的**：豆包无 CORS 头，CDN 有 Referer 防盗链，浏览器直连必被拦。
- **SSL 兼容**：部分容器/代理默认 SECLEVEL=2 会直接 RST 连接，代码里降到 `SECLEVEL=1` + 锁 TLS1.2 才稳定。
- **分享接口必须成对**：`share_id` + `vid` 缺一不可（缺报 `710010202`），邻接雪花 ID 无效，所以无法枚举。
- **视频直链约 7 天过期**，`/api/resolve` 加了 600 秒缓存兜底，广场列表另有 3 分钟缓存（既实时又不打爆豆包）。
